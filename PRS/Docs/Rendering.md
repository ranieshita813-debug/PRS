# Rendering: Vulkan RHI + forward renderer

## Layers

```
Scene (components, hierarchy)
      |
Renderer  -- picks meshes, builds per-object data, records one pass
      |
RHI       -- Device, Buffer, Texture, Pipeline, CommandList, SwapChain (abstract)
      |
Vulkan    -- Engine/Source/Runtime/RHI/Private/Vulkan/*.cpp (the only place that
             includes <vulkan/vulkan.h>)
```

Renderer never sees Vulkan types; swapping in D3D12/Metal means implementing the
same `PRS::RHI` interfaces.

## Frame flow

1. `Renderer::Render(scene, camera, time)` calls `SwapChain::BeginFrame()`: waits
   the frame fence and acquires the next image.
2. Camera: a scene entity with `Transform` (+ optional `Camera`) gives the view
   matrix; projection uses the swapchain aspect. Without a camera a default orbit
   camera is used.
3. Lighting: the first directional `Light` in the scene, direction taken from its
   transform's forward axis; colour and intensity feed the shading term.
4. `CommandList::Begin` → `BeginRenderPass` (clear colour + depth) →
   `SetPipeline` + `SetDescriptorHeap` (camera UBO) → per mesh
   `PushConstants(ObjectData)` + `SetVertexBuffer` + `SetIndexBuffer` +
   `DrawIndexed` → `EndRenderPass` → `End`.
5. `SwapChain::Submit` (waits imageAvailable, signals renderFinished) and
   `Present`.

## Meshes and materials

`MeshRenderer.mesh` names the geometry. `"cube"` and `"plane"` are generated by
the renderer; any other name is loaded as a Wavefront `.obj` through
`Renderer::Assets()` and falls back to a cube (with a warning) when missing.

`MeshRenderer.material`, when set, is a texture path resolved the same way and
used as an albedo override for the whole entity. Otherwise each mesh part uses
the material from its `.mtl` file.

A mesh is uploaded once as one vertex/index buffer with per-part index ranges,
so a multi-material model costs one draw call per material but one buffer pair.

## Asset pipeline (`PRS::Assets`)

- `AssetManager` resolves relative names against ordered search paths
  (default: `Assets`, `../Assets`, `../../Assets`, plus the game's `Assets`) and
  caches decoded data for the session. Missing files are warned about once.
- `ObjLoader`: OBJ + MTL import. Handles `v`/`vt`/`vn`, all face index forms,
  negative (relative) indices, n-gon triangulation, `usemtl` groups (one
  `MeshPart` each), `mtllib`, `Kd`/`Ks`/`Ns`/`d`/`map_Kd`, and generates smooth
  normals for faces that have none.
- `ImageLoader`: decodes uncompressed/RLE TGA (8/24/32-bit) and uncompressed
  24/32-bit BMP to RGBA8. Both are dependency-free; PNG/JPEG need a library and
  are the next step.
- Textures upload as `RGBA8_UNORM` with one mip level; the shader decodes sRGB
  with `pow(2.2)`, so lighting stays linear.

## Data formats

- Colour target: the swapchain's `B8G8R8A8_UNORM`/`R8G8B8A8_UNORM` if offered,
  otherwise the first supported format. Shaders write gamma-corrected values, so
  an UNORM target is preferred over sRGB.
- Depth: `D32_SFLOAT`, cleared to 1.0.
- Albedo (set 0, binding 1): combined image sampler. Untextured materials bind
  a 1x1 white texture so the shader has a single path. Each material owns its
  own descriptor set (camera UBO + its texture).
- Camera UBO (set 0, binding 0): `mat4 viewProjection; vec4 cameraPosition;
  vec4 lightDirection; vec4 lightColor;` (112 bytes).
- Object push constants: `mat4 model; vec4 baseColor; vec4 params;` (96 bytes,
  the guaranteed Vulkan minimum). `params.x` is the specular exponent,
  `params.y` the specular strength.
- Vertex: `vec3 position; vec3 normal; vec2 uv` (32 bytes, three attributes).

## Synchronization

- One frame in flight: the swapchain's fence serialises CPU recording and GPU
  execution. This keeps the first backend simple and correct; increasing it means
  per-frame command lists, UBOs and descriptor sets.
- Semaphores: `imageAvailable` (acquire → render) and `renderFinished`
  (render → present).
- Render passes use `UNDEFINED` initial layouts, so each frame discards the
  previous contents and Vulkan inserts the needed transitions.

## Shaders

- Sources: `Engine/Shaders/Forward.vert.glsl`, `Forward.frag.glsl` (GLSL 450,
  Vulkan target).
- Prebuilt SPIR-V: `Engine/Shaders/Compiled/forward.{vert,frag}.spv`, copied next
  to the binaries at configure time.
- If the Vulkan SDK's `glslangValidator` is on `PATH`, the build regenerates the
  SPIR-V from the GLSL sources every time (`PRS_Shaders` target).
- Shading is Lambert + Blinn-Phong with one directional light, Reinhard tonemap
  and manual gamma. PBR (GGX), shadows, clustered lights and post-processing are
  the next rendering steps; their stubs are already laid out under
  `Renderer/Private/Passes`.

## Running

```
cmake --preset debug
cmake --build --preset debug
./Intermediate/debug/bin/MyOpenWorld   # ESC quits, WASD moves the camera
```

Requirements: a Vulkan 1.1 driver and loader. When `Vulkan` is not found the
engine still builds and runs without rendering (`CreateDevice` returns null and
the app logs that rendering is disabled).

## Known limits

- Asset formats are OBJ/MTL and TGA/BMP; no glTF, PNG or JPEG yet, and no
  normal/specular maps or texture compression.
- No shadows, PBR or offscreen targets (the render pass cache assumes a
  swapchain colour target with `PRESENT_SRC` final layout).
- Box colliders are axis-aligned in physics; rotation is ignored by the
  narrowphase.
- One frame in flight, hard synchronisation at the end of each frame.
